# Проверка рекомендаций и фото — 18.10.2026

Изменения после main PR #23; опубликованный frontend из PR #23 совместим с этим бэкендом.

- Для прогулки на улице сервер исключает помещения, кинотеатры, театры и музеи до генерации. Ограничение действует для локальной базы и 2ГИС, сохраняется при расширении категорий. Явный запрос музея/кино по-прежнему поддерживается.
- Шаблонное действие учитывает тип заведения: кинотеатр больше не предлагает выставку. В объяснении прогулки есть фактические минуты пешком и на месте. Gemini получает подсказку типа занятия.
- Фото 2ГИС сопоставляются только по полученной сервером идентичности места, точному названию, категории и единственному совпадению до 150 м. Неизвестный ID, другое заведение или неоднозначные филиалы возвращают no_photos. Фронтендовый near поддерживается, но не считается доказательством.
- Реальный снимок 1 251 POI переиндексирован: 64 LSA-компоненты, 0 отклонено. Проверка предотвращает незаметный откат поставляемого индекса на BM25.
- Повтор ошибки Gemini в поиске 2ГИС удерживается 30 секунд; после этого ИИ может восстановиться. Каталог и шаблонные карточки доступны при ошибке модели.
- eval/live.py проверяет ID с учётом источника; реальный ID 2ГИС больше не считается выдуманным из-за отсутствия в OSM. По умолчанию проверяется local; доступны --source auto/2gis и --per-scenario 1.

## Локальные результаты

302 Python-теста, 32 теста фронтенда, Ruff — успешно. Два набора по 30 запросов — успешно на реальном снимке без внешних API. Детали: [recommendation_photo_checks.json](recommendation_photo_checks.json).

Проверены: принадлежность карточек кандидатам, 1–3 результата в демо, время с обратной дорогой и резервом, статусы часов, RU/KK/EN, детские и ночные ограничения, приватность, отказ провайдеров, пагинация, фото и совместимость запросов фронтенда.

Эти проверки не подтверждают доступность живой квоты Gemini, фактическую работу заведений или ручную релевантность. После слияния нужен ручной деплой существующего Render Free и проверка публичных сценариев. Фронтенд не изменён; повторная публикация Netlify для этих исправлений не требуется.

## Граница технической приёмки

По исходному ТЗ НИЦ Smart City реализованы автоматический сбор, RAG, веб-демо, контекстные рекомендации и источники/ограничения. Приёмка генерации на публичном сервисе требует фактического ответа mode=ai. HTTP 429 означает внешний лимит; шаблонный режим нельзя объявлять успешной проверкой ИИ. Новые платные услуги или квоты не подключались.

Презентация, итоговый PDF/видео, независимая проверка телефонов, ручные оценки 3×30 и цели полноты данных из внутреннего плана остаются отдельными командными результатами. Они не выводятся из зелёных тестов.
