# 2ГИС: поиск мест, рейтинг и расписание

Состояние доступности меняется с квотой: после отказов, зафиксированных ранее, контрольный прогон 20.10.2026 получил ответы 2ГИС; при обновлении README health сообщает `last_status=ok`. Это последний известный результат, не постоянная проверка ключа. После 403/429 поиск и детали делают общий перерыв на 5 минут; health сам не вызывает 2ГИС. [Исправление Coffee BOOM и публикация](frontend/COFFEE_LOCATION_RATINGS.md).

## Онлайн-поиск в каталоге

При `TWOGIS_ENABLED=true` и `TWOGIS_SEARCH_ENABLED=true` (по умолчанию) обычный `POST /recommend`
использует каталог 2ГИС. Наличие места в `data/poi.json` больше не требуется. Для старого локального
поиска явно передать `source: "local"`; `source: "2gis"` требует именно 2ГИС, `auto` выбирает включённый источник.
В режиме `auto` завершённый пустой поиск или отказ каталога может перейти к локальным местам с теми же ограничениями и явной пометкой источника. Явный `source=2gis` и пагинация не подменяются: сохраняются `source_error`, пояснение или пустая выдача. Старые клиенты без поля `source` используют `auto`.

Результат содержит `source: "2gis"`, `next_cursor`, `recommendations[].facts_source: "2gis"`, адрес,
рейтинг, точную ссылку карточки и стабильный `poi_id=2gis_<id>`.
`recommendations` — до трёх выбранных мест. `nearby_places` — все распознанные места текущей порции,
в порядке расстояния. Закрытые и некоторые неподходящие для плана места могут быть показаны с `eligible=false`
и `excluded_because`; нарушающие обязательные требования по помещению, детям и расходам не возвращаются в этот список. Неизвестные часы не считаются закрытием. `catalog_total` — число результатов
провайдера до нашей проверки рубрик и ограничений, а не число подходящих рекомендаций.

2ГИС запрашивается с `sort=distance`. За пользовательский запрос загружаются до двух страниц по 10 мест.
Наличие нескольких рубрик не должно скрывать кофейню; кафе/рестораны тоже допустимы для запроса кофе.
Имена сетей, в том числе Coffee Boom и Espresso Day, сохраняются в поисковом запросе.
При наличии `next_cursor` отправить исходный запрос с этим `cursor`: следующая порция дополняет список,
а три рекомендации относятся к новым кандидатам. Курсор привязан к запросу, хранит уже просмотренные ID
и действует 5 минут. Предела в пять страниц/50 кандидатов больше нет; действуют квоты провайдера и срок курсора.

Страницы временно кешируются в памяти, до 5 минут, без записи в POI-файл или постоянный индекс.
Ограничитель общий с кнопкой деталей: 20 попыток в минуту, 200 в сутки на процесс.
Если следующая страница не получена, уже загруженные места остаются доступны и возвращается курсор повтора.
Интерфейс не стирает прежние места при ошибке следующей порции. Ошибки не подменяются местами из локальной базы.

При наличии `GEMINI_API_KEY` проверенные кандидаты из 2ГИС передаются существующему Gemini:
название, рубрики, рейтинг, расстояние, расписание и допустимое время посещения. Код выбирает и ранжирует до трёх мест; Gemini пишет объяснения и идеи занятия по их фактам. Сервер проверяет текст и заменяет отклонённые карточки шаблоном.
Неизвестные розетки/Wi-Fi не объявляются подтверждёнными. Закрытые и неподходящие по жёстким ограничениям
места не отправляются как кандидаты для выбора. При ошибке Gemini остаётся выдача 2ГИС с честной пометкой
`mode=no_ai`; `mode=ai` требует хотя бы одной принятой генерации с `why_source=ai`. `selection_source=rules` сохраняется: модель не меняет порядок мест.
Проверенные ответы Gemini временно кешируются в памяти, до 5 минут; часы и доступность перепроверяются
перед каждой сборкой ответа. `source=local` сохраняет прежний локальный RAG.

## Публикация интерфейса Алиханом

Взять из `main` обновлённый frontend из main, включая `frontend/app.js`, `frontend/i18n.js`, `frontend/sw.js`, `frontend/about.html`, `frontend/index.html`
и опубликовать на Netlify. Сохранить остальные файлы, особенно `img/places/index.json` и фотографии.
Обновление показывает все загруженные места на карте и в списке, добавляет «Загрузить ещё места»,
сохраняет три рекомендации Gemini и обновляет описание передачи данных ИИ.
Бэкенд обновляется отдельно на Render. Ключи во фронтенд не добавлять.

## Подключение

В Render → seruen-backend → Environment:

- `TWOGIS_API_KEY`: отдельный демоключ 2ГИС, только на сервере.
- `TWOGIS_ENABLED=true`: включает обработчик. `false` немедленно отключает его после деплоя.

Локальный `.env` не требуется. Перезапуск должен включать новый код из `main` и сохранённые переменные.
Ключ не добавлять в GitHub, config.js, URL сайта, клиентские запросы или сообщения.
Google Places остаётся отдельно выключенным; Gemini продолжает работать независимо.

`GET /health` содержит `twogis.configured`, `enabled`, `search_enabled`, `last_status`, `photos_supported=false`.
`configured=true` означает наличие ключа, **не** его работоспособность. `not_checked` — нормальный статус до первого запроса:
при старте и проверке здоровья обращения к 2ГИС не выполняются.

## Контракт для Алихана

```http
GET /places/{poi_id}/2gis?lang=ru
```

`poi_id` берётся из существующих рекомендаций. `lang`: `ru`, `kk`, `en`; для `en` запрашивается русский ответ
с явным `language=ru`, поскольку `en_KZ` отсутствует в списке локалей API. Ключ передавать не нужно.

Ответ содержит:

- `source=2gis`, `provider_name`, `address`, `provider_url`, `attribution`, `checked_at`;
- `rating`, `rating_count`, `rating_scope` (`branch`, `organization`, `unknown`);
- `weekly_hours`: дни `Mon`–`Sun`, интервалы `start`/`end`;
- `special_hours`: даты и интервалы праздничного/специального расписания;
- `is_24x7`, `schedule_note` — дополнительные сведения провайдера;
- `match_method`, `match_distance_m` — способ сопоставления с нашей OSM-точкой;
- `open_now=null`: наличие расписания не является подтверждением работы прямо сейчас;
- `photos_supported=false`: самих фотографий официальный Places API 2ГИС не выдаёт.

Отсутствующие рейтинг/часы не заменять нулями или фразой «закрыто». Не называть `rating_count` числом оценок со звёздами:
это количество отзывов, которое вернул провайдер. `organization` относится к организации, а не гарантированно одному филиалу.

Вызывать только по кнопке «Рейтинг и часы 2ГИС», без запросов для каждой карточки/всей базы при загрузке.
Показывать отдельный блок с названием/адресом из ответа, подписью «Данные 2ГИС», ссылкой `provider_url` и временем проверки.
Данные о работе сейчас не смешивать с симулированным временем сценария и статусами OSM.
Содержимое API выводить через `textContent` или экранировать, не вставлять как HTML.

## Сопоставление и ограничения

Если в POI есть вручную проверенный `twogis_place_id`, используется официальный `/items/byid`.
Иначе выполняется один поиск по названию в радиусе 150 м от **координат места из базы**, а не пользователя.
Нужны точное нормализованное совпадение названия (основного/RU/KK/EN) и координаты в пределах 150 м.
Неоднозначные/неполные результаты и безымянные объекты отвергаются. Это консервативная автоматическая привязка,
а не гарантия идентичности филиала; название и адрес из 2ГИС остаются видимыми.

Данные не записываются в `poi.json` или постоянный индекс RAG. Кандидаты онлайн-поиска передаются Gemini, как описано выше.
Страницы онлайн-поиска кратковременно живут в оперативной памяти, как описано выше.
HTTP-ответы имеют `Cache-Control: no-store`. Автоматического сбора фотографий или обхода сайта 2gis.kz нет.
Существующий `/places/{poi_id}/details` по-прежнему относится только к Google и не изменён.

Документация 2ГИС на 18.10.2026: демоключ действует месяц; для Places API — 1 000 запросов за пробный период.
Дополнительно приложение разрешает до 20 попыток в минуту и 200 в сутки UTC на процесс. Счётчик приложения сбрасывается
при рестарте и не заменяет общий лимит 2ГИС. Использовать именно demo, не переводить ключ на платную подписку автоматически.

## Ошибки

| Код | HTTP | Значение |
|---|---|---|
| `twogis_disabled` | 503 | Выключено или MOCK_MODE |
| `twogis_not_configured` | 503 | Нет ключа |
| `poi_not_found` | 404 | Неизвестный ID нашей базы |
| `twogis_not_matched` / `twogis_not_found` | 404 | Надёжной привязки нет |
| `twogis_match_ambiguous` | 409 | Несколько совпадений или результат не помещается в ответ |
| `twogis_access_denied` | 503 | Ключ отклонён/нет доступа к методу |
| `twogis_local_limit` | 429 | Достигнут локальный ограничитель |
| `twogis_quota_exceeded` | 429 | Лимит провайдера |
| `twogis_timeout` / `twogis_unavailable` | 503 | Временный сбой |
| `twogis_invalid_response` | 502 | Некорректный ответ провайдера |

Сбой 2ГИС не мешает явно выбранному локальному режиму (`source=local`). В логах сохраняются только фиксированные категории ошибок.

## Проверка

33 новых теста проверяют привязку филиалов, неоднозначность, отсутствие данных, расписание, ошибки HTTP/meta,
защиту ключа, языки, ограничения параллельных запросов, отсутствие запросов при старте и неизменность POI.
После добавления поиска полный набор: **277 Python-тестов и 29 тестов фронтенда**, Ruff проходит.
Проверены новые места вне POI-базы, пагинация без повторных запросов, курсоры, ошибки/квоты,
строгие фильтры, отсутствие обращений на старте, локальный режим, прямые ID и параллельные запросы.
Тесты используют поддельный HTTP-транспорт и не расходуют квоту.
Фактический доступ к внешнему API подтверждается отдельно одним-двумя запросами после деплоя.
