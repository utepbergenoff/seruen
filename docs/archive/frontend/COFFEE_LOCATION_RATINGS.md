Источник — [карточка филиала](https://2gis.kz/astana/firm/70000001072135261) и её ссылка «Маршрут». Это точка заведения, не подтверждённый вход.
- Ссылка карточки ведёт к проверенному ID филиала, а не поиску по длинному командному названию. Другие Coffee BOOM не получают его координаты, фото или отзывы. Неоднозначная группа ID не выбирается наугад.
- Рекомендация, метка и маршрут используют одну точку. Для старой вкладки сервер пересчитывает финиш по `finish_poi_id`, даже если пришли прежние координаты.
- При отказе API доступны «Отзывы в 2ГИС» (проверенный филиал) или «Найти отзывы в 2ГИС» (без подтверждённой связи, нужно проверить адрес). Рейтинг не выдумывается и не копируется из веб-страницы.
- Поиск и детали имеют общий пятиминутный перерыв после отказа/исчерпания квоты. `/health.last_status` отражает и ошибки деталей. Шестичасовой запрет в браузере удалён: восстановленный провайдер больше не скрывается старой настройкой.
- При `rating:null`/`0` и наличии `general_rating` поиск и детали согласованно используют общий рейтинг и его число отзывов. Детали обозначают неизвестную область оценки.
- Достопримечательность сохраняет описание и Википедию при смене ID провайдера благодаря проверенному `canonical_id`.
- Переводы шести сценариев синхронизированы между фронтендом и сервером; параметры запросов не менялись.
- Первый поиск получает возможности сервера параллельно с погодой и затем передаёт выбранный режим финиша. Устранена гонка, из-за которой интерфейс показывал «остаться в месте», а ранний запрос рассчитывался с возвращением.
