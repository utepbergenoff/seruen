## 1. Концепция продукта

**Проблема.** Карты (2GIS, Google Maps) отвечают на вопрос «где находится X». У человека у Mega Silk Way с 40 свободными
минутами вопрос другой: *что мне сейчас делать рядом* — с учётом времени, погоды, того, что он с ребёнком или хочет тишины.

**Решение.** «Серуен» (каз. *серуен* — прогулка) — городской советчик. Вы говорите, где вы и чего хотите; за несколько
секунд он предлагает 1–3 конкретных места рядом с честным «почему», временем, планом «что там делать» и маршрутом —
опираясь только на собранную базу мест Астаны и показывая, в чём он не уверен.

**Для кого.**

| Сегмент | Момент потребности | Типичный запрос |
|---|---|---|
| Жители | «Есть час, не хочу домой» | «Я возле Mega Silk Way, хочу прогуляться 30–60 минут» |
| Родители с детьми | Интересно и безопасно для ребёнка | «Я с ребёнком, есть час, куда сходить рядом?» |
| Туристы и командировочные | Окно 1–3 часа | «У меня 2 часа перед вылетом, что посмотреть?» |
| Студенты и удалёнщики | Место для работы вне дома | «Тихое место с кофе и розеткой недалеко» |

**Чем отличаемся:** веб + телефон с картой и пресетами; ИИ выбирает только из мест, найденных кодом (0 выдуманных
мест); радиус считается из бюджета времени; честная шкала «открыто?»; метки «из базы / идея ИИ»; работает без ключа ИИ.

## 2. Как работает RAG (высокоуровнево)

**Офлайн (раз в сутки, одна команда `python -m pipeline.run`):** OpenStreetMap → разбор часов работы → сопоставление
с Google Places → описания из Wikipedia → короткие описания по тегам (с пометкой) → чистка и дедупликация → база
`data/poi.json` + отчёт о качестве.

**Онлайн (на каждый запрос, цель ≤ 5 с):** локация (округлена до ~100 м) + текст + контекст → разбор запроса →
**код** находит кандидатов: радиус из бюджета времени, фильтры (категория, «открыто», дети, доступность), баллы →
**Gemini** выбирает 1–3 места *только из кандидатов по id* и предлагает длительность строго по схеме JSON →
**код** проверяет id и длину, считает расстояние, минуты и статус, формирует «почему» и «что делать» по фактам → ответ.

Принцип: **код проверяет ограничения — ИИ помогает выбрать — факты объясняют выбор.** Без ключа Gemini — режим «без ИИ»: топ-3 по баллам и шаблонные объяснения.

Радиус: скорость 75 м/мин (с ребёнком 60), коэффициент улиц 1,3; радиус = (бюджет − время на месте) ÷ 2 × скорость ÷ 1,3.
Пример: 60 мин, на месте 30 → ≈ 865 м по прямой.

⏳ Схема (рис. 1 из плана) — та же, что на слайде 4.

## 4. Правила для сомнительных и неполных данных (FR-9)

⏳ Томирис: сверить формулировки с текстами в коде.

| Ситуация | Правило — и что видит пользователь |
|---|---|
| Нет часов работы | Статус «неизвестно» + «проверьте перед визитом»; место не исключается, но ниже открытых |
| Закрыто по расписанию сейчас | Исключается из выдачи «сейчас»; при запросе «на вечер / завтра» — по расписанию на то время |
| Временное событие | Только с датой и источником, пометка «событие» |
| Пусто в радиусе | Радиус ×1,5 один раз и честное сообщение; если пусто — «рядом ничего подходящего не нашёл» |
| Запрос вне Астаны / не о прогулке | Вежливый отказ |
| Противоречие (бюджет 30 мин, место в 40) | Честно: «в 30 минут ничего такого нет; ближайшее — в 40»; альтернатива ближе |
| О месте мало данных | Не придумываем детали: «в базе только категория и адрес» |
| Gemini недоступен | Режим без ИИ, пометка «режим без ИИ» |
| Подозрительная запись (нет координат, дубль, мусор) | Отсеивается в конвейере; счётчик — в отчёте о качестве |

## 5. Данные и их ограничения

Источник цифр — `data/quality_report.md` (генерируется конвейером; дата сборки указана в отчёте).
⏳ Ерлан: обновить цифры после финальной сборки.

| Показатель | Значение |
|---|---|
| Мест в базе | 1 251 в 12 категориях (`cowork` — 1 место, `unusual` — 2: в открытых данных их почти нет) |
| С часами работы | ~21 %; разбирается 100 % строк часов |
| С описанием | 100 %: Wikipedia — 22 места, остальные — сгенерированы по тегам и помечены |
| С данными о доступности | ~5 % (OSM) |
| Отсеяно | 181: без названия 104, дубликаты 74, мусор 3 |
| Рейтинги | не хранятся: условия Google Maps Platform запрещают хранить контент; в базе только `place_id` |

**Ограничения системы.**

- Данные OpenStreetMap могут устареть; покрытие неравномерно по районам.
- Часы работы известны у меньшинства мест — поэтому статус часто «неизвестно», и мы этого не скрываем.
- Часть описаний сгенерирована по тегам (ИИ или шаблон) — помечено полем `description_source`.
- Рейтингов нет в снимке данных (см. выше); популярность — оценка по признакам OSM, так и подписана.
- Мало коворкингов и «необычных» мест в открытых данных — для этих сценариев используются кофейни, библиотеки,
  смотровые и музеи.
- Маршруты — по формуле расстояния, если сервис пеших маршрутов недоступен.
- События не в реальном времени.

## 6. Этика и приватность

**Конфиденциальность локации.** Координаты округляются до ~100 м на устройстве до отправки. Нет аккаунтов и cookies-
трекинга. Сервер не пишет в логи координаты и тексты запросов — только счётчики. Ключ кеша — хэш.
Режим без геолокации: точка на карте или пресет.

**Что уходит в Gemini:** текст запроса, округлённая локация, список кандидатов из базы. Никаких идентификаторов
пользователя. При сборке данных в Gemini уходят только название, категория и признаки мест — без пользовательских данных.

**Борьба с недостоверной информацией.** Шкала статуса «открыто / вероятно открыто / неизвестно / закрыто» с источником
и датой; слово «открыто» без данных о часах запрещено (тест). Метки «из базы» / «идея ИИ». ИИ не может назвать место
не из базы: любой чужой id отбрасывается и считается (в eval — 0). Описания из Wikipedia принимаются, только если статья
о месте в Астане и, для памятников, о самом памятнике, а не о человеке — лучше без описания, чем с чужим.

**Безопасность пользователей.** Ночью — людные работающие места, радиус ≤ 1 км, заметка «возвращайтесь на такси /
транспорте». С ребёнком — бары и места 18+ исключены. При сильном холоде или ветре — предупреждение и крытые места.
Не рекомендуем опасные активности; не даём медицинских и юридических советов. Дисклеймер в каждом ответе:
«Данные о местах могут устареть — проверяйте на месте».

## 8. План развития и риски

**Дальше:** официальный источник часов работы городских объектов и событий (от города); живые рейтинги через API при
наличии ключа; больше коворкингов и необычных мест (проверенный вручную список); групповой режим; события недели;
офлайн-режим; интеграция в городское приложение; другие города (конвейер работает по координатам любого города).

**Риски:** квоты API (смягчено режимом без ИИ и кешем); устаревание данных (дата проверки в каждом ответе);
неполные часы (честный статус «неизвестно»).
