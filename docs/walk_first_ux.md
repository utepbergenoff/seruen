# Прогулка без потери цели — обновление 19 октября 2026

## Поведение

- Перед началом и сохранением прогулки человек выбирает финиш: последнее выбранное место, возврат к началу или другая точка (ориентир / карта). Выбор общий для обычного поиска, встречи и достопримечательностей. Неявного возврата больше нет.
- В режиме прогулки видны её остановки, финиш и действия. Поиск и сценарии скрыты. «К местам · маршрут сохранён» возвращает карточки; «Продолжить прогулку» возвращает маршрут. Новый поиск открывается отдельной кнопкой. Выбор метки и «Назад» не очищают результаты.
- После старта на карте остаётся одна линия активного маршрута. Выбранное место не подменяется первой рекомендацией. Если сервер исключил одну из запрошенных остановок, клиент не начинает изменённый маршрут молча.
- «Замёрзли» / «Устали» предлагают остановку впереди по направлению к следующей цели. Проверенные общественные лавочки имеют приоритет для отдыха. Предложение применяется только после нажатия «Добавить остановку», прежние остановки и финиш сохраняются. При отсутствии подходящего места остаётся текущая прогулка.
- Карточки показывают опубликованные часы, дату, источник 2ГИС, ссылку, недельный график и оговорку о возможных изменениях. Специальные часы на выбранную дату имеют приоритет. Отсутствующий день не превращается в выходной.
- Доступные атрибуты из 2ГИС показываются с источником. Средний чек, Wi-Fi и другие признаки не доказывают бесплатный вход: при отсутствии данных текст прямо говорит, что цена входа не указана. Проверенные условия команды сохраняются отдельно.
- Условия доступны и у выбранных мест вне топ-3. На виду максимум четыре атрибута с приоритетом полезных условий; длинный перечень 2ГИС раскрывается отдельно.
- Во встрече есть «Ваш старт · точка A» и «Старт второго участника · точка B», нормальные названия ориентиров, выбор заведения на карте/в карточке и возврат ко всем местам встречи.
- Убран общий декоративный предпросмотр со слайдером. Для маршрута из встречи/достопримечательности остаётся краткий обзор: остановки, время, финиш и начало прогулки. Устаревший расчёт нельзя запустить без обновления.
- «Истории» в интерфейсе переименованы в «Достопримечательности». Есть список ближайших и метки. Каталог расширен с 20 до 26 объектов. Шесть новых: памятники Кенесары, Абаю, Богенбаю, театр Горького, Astana Ballet и мост Атырау. Источники указаны; Wikipedia — только там, где есть подходящая статья, иначе официальный источник.
- Включён небольшой фикс из ветки коллеги `fix/team-place-2gis-alias`: проверенный алиас собственной точки используется для получения точных сведений 2ГИС.

## Границы точности и оплаты

Остановка должна лежать впереди до следующей цели, не дальше 450 м от текущей точки и не дальше 100 м от прямого коридора. Добавочный оценочный путь ограничен 180 м; после расчёта проверяются первые два перехода, добавка не больше 3 минут. Это консервативный фильтр: он может не предложить место, если улицы сильно обходят препятствие. При недоступном маршрутизаторе линия явно помечена приблизительной. Это не навигатор и не подтверждение прохода через двор, состояния льда или доступности входа.

Для пересчёта используется текущая синяя точка карты. Если человек переместился, её нужно обновить; скрытого непрерывного слежения нет. Запоздавший ответ для прежней точки не применяется.

Новые платные сервисы, планы, ключи, базы и фоновые опросы не добавляются. Атрибуты 2ГИС запрашиваются в уже существующем запросе каталога. Доступность внешних API и их прежние квоты остаются ограничением. Названия/координаты 2ГИС не добавляются в постоянное офлайн-хранилище.

## Проверки

438 серверных тестов и 114 интерфейсных тестов. Среди них интеграция настоящего FastAPI с интерфейсом на синтетическом наборе, выбор всех вариантов финиша, сохранность выбранных остановок, отбрасывание мест позади/сбоку, сохранность цели при отдыхе, гонки запросов, специальные часы и экранирование текста источника.

В локальном браузере проверены выбор конкретной карточки, подтверждение финиша, добавление лавочки перед целью, скрытие сценариев, возврат к карточкам и продолжение прогулки. Это проверка подготовленного интерфейса; обновление бэкенда не публикует Netlify автоматически.

После публикации PR #49 на Render проверены живые ответы: 26 достопримечательностей, CORS Netlify GET/POST, два разных финиша, добавление `team_comfort_nurzhol_bench_1` перед Байтереком с сохранением цели, пустой ответ лавочек позади, семь филиалов Coffee BOOM из 2ГИС с опубликованными часами и атрибутами. В этом поиске ответы были `mode=no_ai`: работа живого Gemini этой проверкой не подтверждена.

## Алихану: как опубликовать

1. После мержа взять актуальный `main`. Публиковать **всю** папку `frontend`, без смешивания файлов из старой сборки. В `sw.js` версия кеша `seruen-v27-walk-first`.
2. `config.js` уже содержит `https://seruen-backend-f36d.onrender.com`. Ключи и платные настройки не нужны.
3. После публикации обновить страницу. Проверить: выбрать второе место → начать → выбрать финиш → «Устали» → предложение или понятное отсутствие → цель сохранена. Проверить «К местам», «Продолжить прогулку», встречу с выбором места, часы и достопримечательности.
4. Сверить `/health`: `features.on_route_breaks=1`. До обновления сервера новый интерфейс не включает пересчёт с обещанием остановки по пути.

Ерлану: для расширения покрытия нужны подтверждённые лавочки и тёплые входы вдоль пеших маршрутов. Координаты, условия доступа, источник и дата проверки обязательны; не выводить наличие лавочки из самого факта существования парка.
# Accepted stops use pedestrian routes — 2026-10-19

The router now waits within the current request for its one-second slot (bounded to 2.5 seconds), without storing coordinates or retrying the provider. When street routing is enabled, an additive break requires a successful pedestrian baseline and full route through the new stop and all remaining goals. A routing failure returns `409 break_routing_unavailable`; the current walk remains intact. Added distance/time is compared against the pedestrian baseline, not a straight-line estimate. No new provider or paid service.

The frontend guards against replacing a street route with an estimated break from an older backend, offers retry, keeps accepted stop markers clickable, fits the new path on screen, and checks that the user's point has not moved since the proposal.
