# Подготовка Heroku — резервный вариант бэкенда

Текущая работающая схема: сайт на Netlify → API, RAG и снимок мест на Render Free. Подготовка Heroku не меняет эти адреса. Ключи Gemini/Google отключены по решению пользователя. Публичный деплой Heroku ещё не выполнен.

## Что подготовлено

- `.python-version`: Python 3.12 с последним доступным патчем Heroku.
- `Procfile`: один web-процесс Uvicorn, адрес `0.0.0.0`, порт из `PORT`, ограничение потоков NumPy; используются существующие обезличенные логи.
- `bin/post_compile`: пересобирает LSA-индекс из снимка при сборке. Применяется к классическому Python buildpack (Cedar), не к Fir/CNB. BM25 создаётся при старте.
- `.slugignore`: исключает тесты, сырые выгрузки и локальные файлы; `data/poi.json`, `data/demo_scenarios.json` и `data/index` остаются.

Локальная проверка выполнена в отдельной временной копии: build hook создал индекс на 1 251 месте / 64 измерениях; точная команда Procfile запустила API на переданном PORT; 6/6 демо, бюджеты, кеш и CORS прошли. Рабочий Render также отвечает с 1 251 местом. [Отчёт](heroku_preparation_verification.json). Это проверка команд локально, не сборка или запуск в облаке Heroku.

## После фактического начисления кредитов

1. Войти в Heroku и проверить в Billing сумму, срок действия и доступность кредитов для выбранного плана. Ожидаемые кредиты не считать начисленными. Для этой задачи разрешены только расходы, полностью покрытые кредитами; обычную платную подписку не запускать.
2. Создать личное приложение Cedar с классическим buildpack `heroku/python`. Для минимальной конфигурации нужен один Eco web dyno; базы данных, Redis, диски и дополнения не требуются. Точный адрес выдаёт Heroku, его нельзя угадывать по имени приложения.
3. Задать переменные из таблицы, подключить репозиторий `utepbergenoff/seruen`, ветку `main` после объединения PR подготовки. Если доступа к репозиторию нет, владелец должен разрешить интеграцию GitHub или передать доступ к приложению. Секреты в Git не добавлять.
4. Выполнить деплой, проверить сборку индекса и запуск web-процесса. В `/health` ожидаются `poi_count=1251`, `data_kind=real`, `retrieval_mode=bm25+lsa`, `mode_available=[no_ai]`, `mock=false`.
5. Проверить `/docs`, 6 демо, 30 сценариев Ерлана, ночь, бюджеты и CORS с домена Netlify на новом адресе. Только после этого заменить адрес API во фронтенде и опубликовать сайт. Проверить реальные карточки и карту в браузере.

| Переменная | Значение |
|---|---|
| POI_PATH | data/poi.json |
| DATA_KIND | real |
| WARM_CACHE | true |
| MOCK_MODE | false |
| OPENBLAS_NUM_THREADS | 1 |
| OMP_NUM_THREADS | 1 |
| CORS_ORIGINS | https://seruen-astana.netlify.app,http://localhost:5173,http://127.0.0.1:5173,http://localhost:3000 |

`PORT` назначает Heroku. `HOST=0.0.0.0` уже задан Procfile. `GEMINI_API_KEY` и ключи Google не задавать.

До завершения проверки Heroku рабочим адресом остаётся Render. Откат — вернуть этот адрес API во фронтенде. Два бэкенда могут существовать одновременно, но текущий сайт использует один выбранный адрес; автоматического резервирования сейчас нет. У каждого процесса свой кеш, который исчезает при перезапуске. Данные и индекс включены в сборку, поэтому отдельная база не требуется.

## Стоимость и ограничения

Heroku Eco — подписка $5/месяц с общими 1 000 часами на аккаунт, с засыпанием после простоя. Это не бесплатный тариф. Начисленные кредиты могут покрывать счёт; после их окончания ресурсы нужно остановить или оплачивать. На этапе подготовки платные ресурсы не создаются. Render Free остаётся текущим хостингом до отдельного перехода.

Источники: [Eco](https://devcenter.heroku.com/articles/eco-dyno-hours), [Python](https://devcenter.heroku.com/articles/python-support), [Procfile](https://devcenter.heroku.com/articles/procfile), [build hook](https://github.com/heroku/heroku-buildpack-python/blob/main/bin/compile).
