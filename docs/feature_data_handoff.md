# Ерлану: данные для восьми функций

Подключён набор Ерлана `3bca9f4`: 17 удобств, 24 условия посещения, 9 групп ID (10 алиасов), 8 примеров атмосферы. [Источники и оставшиеся проверки](feature_expansion_data.md). Удобства и расходы пока unverified и не считаются подтверждёнными. Исходный `data/poi.json` не изменён. Дополнения через свою ветку `feat/*` → PR в `main`.

## Файлы и проверка

Каждый файл: `{"version":1,"items":[...]}`. UTF-8, максимум 5000 записей/5 МБ. Неизвестные поля запрещены. Машинные схемы: [schemas](schemas/). Проверка без ключей и сетевых запросов:

```bash
python scripts/validate_feature_data.py
```

Ожидается status=valid и реальные количества записей. Код возврата 1 означает ошибку; не загружать такой набор. На сборке Render та же проверка включена в reindex. Для другой папки: `--data-dir путь --poi data/poi.json`. Для пересоздания схем: `--write-schemas docs/schemas`.

| Файл | Содержимое записи |
|---|---|
| feature_pois.json | Собственное описание места: poi (старый POI-контракт), evidence, offline_allowed, license, attribution |
| comfort_points.json | То же + kind (warming/toilet/bench/water/entrance), access (public/customers_only/paid/unknown), floor (строка/null) |
| visit_conditions.json | poi_id, kind (free/optional_purchase/paid/unknown), evidence |
| poi_identity_links.json | canonical_id, aliases (1–10), evidence |
| atmosphere_catalog.json | example_id, poi_id, title, titles (ru/kk/en), features, photos, evidence, analysis_source (manual/gemini), analysis_version |

Общий `evidence`: source_url (публичная ссылка на основание/отчёт проверки), checked_at (YYYY-MM-DD), verification (verified/unverified/conflicting), method (field_visit/official_source/licensed_source/team_review), note (до 800 символов). Не ставить verified без проверки. Не публиковать личные адреса, номера участников и внутренние секреты.

## Удобства и собственные места

Собственные ID вида `team_*`, уникальны и не переопределяют исходные OSM/2ГИС-записи. Только координаты в Астане. Вложенный `poi` соответствует существующему контракту (обязательны poi_id/name/lat/lon/category); отсутствие расписания, доступности и дружелюбности к детям не превращать в подтверждение. category остаётся старой категорией POI, точный вид удобства задаётся kind. Источник/дата проверки, условия доступа, этаж и примечание описывают конкретную точку/вход.

Подтверждение удобства действительно 30 дней, собственной записи — 90. Посещение кафе не подразумевает свободный туалет; вход в ТРЦ не доказывает доступность всех этажей. Состояние unknown разрешено для показа с оговоркой, но не как гарантированная остановка.

`offline_allowed=true` только для сведений, которые мы вправе хранить и распространять офлайн. Нужны license и attribution. Нельзя скопировать ответ 2ГИС в собственный файл и обозначить разрешённым без прав. Собственное наблюдение/описание можно оформить отдельно от каталога.

## Расходы

- free: подтверждённо бесплатно для указанного действия.
- optional_purchase: можно находиться/посетить без обязательной покупки; покупка факультативна.
- paid: подтверждён обязательный платёж/покупка.
- unknown: нет уверенной информации либо условия конфликтуют.

Указывать условия и границы в evidence.note. Не объявлять кофейню бесплатной по умолчанию. Через 30 дней verified переходит в stale/unknown до новой проверки. Для существующего места использовать точный POI ID; для каталога — `2gis_<числовой ID>`.

## Связи ID и филиалы

canonical_id должен существовать в исходной базе или собственных местах. aliases — другие проверенные ID того же физического филиала (включая `2gis_*`). Нужен evidence.verification=verified. Группы не пересекаются; цепочки/циклы запрещены. Проверять координаты, адрес и филиал вручную, одного совпадения названия недостаточно. Так посещённое место не вернётся под ID другого источника.

## Атмосфера

`title` — обязательное резервное название (1–200 символов); `titles` — переводы `{ "ru":"…", "kk":"…", "en":"…" }`, каждый 1–200 символов. Казахские названия и тексты кнопок нужно проверить носителю языка. Пустой titles допустим, но интерфейс тогда использует title.

Разрешены только видимые признаки: natural_light, bright, dim, greenery, open_space, small_space, visible_seating, modern, traditional, unusual_architecture, outdoor, indoor. Один или несколько признаков, без выводов о Wi-Fi/тишине/свободных местах/часах. Записи привязаны к существующему месту или его проверенному alias. Подтверждение не старше 90 дней.

Каждое фото: photo_id, url (https), content_sha256 (64 строчных hex-символа от фактического файла), license, attribution, offline_allowed. 1–4 фото на пример. Фото другого филиала запрещено; один и тот же hash не может принадлежать разным местам. Лицензия и авторство обязательны, но наличие строки не заменяет проверку прав. Прямые ссылки публикует Алихан; в этом выпуске офлайн-фото не экспортируются.

Для ручной разметки analysis_source=manual, analysis_version=manual-v1. Для ранее выполненного Gemini-анализа — gemini и версия анализа, затем ручная проверка evidence. При изменении изображения пересчитать SHA-256 и проверить признаки; при изменении анализа обновить analysis_version. Новые файлы меняют fingerprint и инвалидируют кеш рекомендаций. Новые API не требуют повторного вызова Gemini при каждом выборе эталона.

```bash
python -c "import hashlib,pathlib; print(hashlib.sha256(pathlib.Path('photo.jpg').read_bytes()).hexdigest())"
```

## Порядок передачи

1. Заполнить небольшую проверенную подборку в этих файлах; оставить unknown там, где нет основания.
2. Добавить фото/ссылки и подтверждения прав, проверить точный филиал.
3. Запустить валидатор и тесты. Пустой файл валиден, но не означает готовые данные функции.
4. В PR указать реальные количества, даты проверки, какие права дают офлайн-хранение, оставшиеся пробелы.
5. После слияния и деплоя проверить `/features/status`, удобства и примеры атмосферы; пройти сценарии на сайте вместе с Алиханом.

Примеры ответов [examples/features](examples/features/) получены на искусственных тестовых данных. Не переносить их заведения, даты и лицензии в production.
