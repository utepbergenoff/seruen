## Интеграция для Алихана

1. Старый `/recommend` остаётся рабочим. Новые необязательные поля описаны ниже.
2. Карточки — варианты выбора. Последовательную прогулку рассчитывать через `/plans/build`; показывать серверные `legs`, `budget`, `fits`, предупреждения и финиш. Не складывать независимые бюджеты карточек.
3. Передавать возвращённый `state` в `/plans/recalculate`, новую текущую точку и **оставшееся** время. Выполненные остановки — только из `state.remaining_ids`.
4. Личные отметки/заметки, ID и подпись места (название, категория, адрес — чтобы «Мои места» показывали название после перезагрузки) хранить только в этом браузере. Для координат требуется подтверждённый offline_allowed; координаты и прочие факты 2ГИС остаются в памяти вкладки, закладка 2ГИС хранит ID, подпись и личную заметку со ссылкой на 2ГИС. На сервер отправлять только необходимые ID и ограничения, без заметок. Для отмены вернуть предыдущий снимок `preferences` и `context.exclude_categories`, убрать `feedback`.
5. Показывать `unknown`, `verification`, дату и источник. Кнопка ослабления фильтра требует действия пользователя; сервер фильтры сам не снимает.
6. F4/F5 и полный экспорт F6 требуют проверенных данных Ерлана. Включена проверка Ерлана `4b31bfb`: 16 удобств (15 verified), 24 условия (13 verified); 15 собственных проверенных точек доступны для офлайн-экспорта. Пустые ответы — штатное состояние, не ошибка сети. `/features/status.data` показывает количество загруженных записей, `ready` — проверенных и свежих; identity_aliases считает только алиасы без канонических ID. Новые API не создают монет, сундуков или аккаунтов.

## F3, F5, F7, F8: общий запрос рекомендаций

Необязательный `request_id` (1–40 символов) возвращается в успешном `/recommend` и не дробит кеш. Остальные запросы не требуют correlation ID; фронтенд защищает их от устаревших ответов локальным номером операции. Ошибки сохраняют прежний формат error.code/fields.

`preferences.max_distance_m`: 50–10000 м от текущей точки; применяется к обоим источникам до ИИ и не расширяется автоматически. Исключений максимум 200: переполнение возвращает понятную ошибку, старые ID не отбрасываются. Для замены одной карточки фронтенд исключает ID всех текущих карточек при запросе замены и заменяет только выбранную.

`end` в `/recommend` считает карточку по схеме начало → место → финиш. В budget_breakdown: walk_back_min=0, walk_to_end_min заполнен, total_min включает обе дороги, посещение и резерв. arrival_estimate — оценка прибытия к финишу без резерва. Карточки используют расстояние ×1.3; серверный `/plans/build` затем проверяет последовательную прогулку по улицам. Если даже прямой путь не помещается, recommendations пуст и route_impossible содержит reason=budget, need_min и предложения. При финише вне Астаны возвращается отказ с пояснением.

```json
{
  "location": {"lat": 51.128, "lon": 71.430, "source": "map"},
  "query": "Хочу кофе",
  "source": "auto",
  "context": {"time_budget_min": 90, "lang": "ru"},
  "preferences": {
    "exclude_poi_ids": [], "visited_poi_ids": [], "exclude_visited": false,
    "preferred_categories": [], "max_walk_min": 10, "indoor_only": false,
    "expense_mode": "any"
  }
}
```

`source`: `auto` использует 2ГИС при включённом каталоге, `local` — локальные данные, `2gis` — каталог. Сбой явно выбранного 2ГИС не маскируется местами из другой базы. Поиск ограничен квотой и областью поиска, не является полной выгрузкой 2ГИС.

`exclude_poi_ids` и `visited_poi_ids`: до 200 уникальных ID длиной до 120 символов. При переполнении возвращается 422; старые исключения не удаляются. `max_walk_min`: 1–120 минут до отдельной остановки; общий предел прогулки — `context.time_budget_min`. `preferred_categories` — категории существующего контракта; пустой массив не добавляет ограничение. Исключение категорий остаётся в `context.exclude_categories`.

`expense_mode`: `any`, `free_only` (только подтверждённое `free`), `no_required_purchase` (`free` либо `optional_purchase`). Цена не выводится из категории, рейтинга или отсутствия данных. Записи старше 30 дней, конфликтующие и неподтверждённые имеют `kind=unknown` и не проходят строгие фильтры.

Необязательный `feedback`:

| reason | Дополнительные поля | Действие |
|---|---|---|
| `too_far` | `max_walk_min` необязательно, по умолчанию 5 | Сократить предел ходьбы |
| `already_visited` | `poi_id` обязательно | Добавить в посещённые и включить исключение |
| `different_place` | `poi_id` обязательно | Исключить конкретное место |
| `wrong_type` | `category` обязательно | Добавить категорию в исключения |
| `no_expense` | — | Включить `no_required_purchase` |

Дополнения к ответу `/recommend`: `applied_preferences`, `change_codes`, `relaxation_options` и короткая локализованная заметка. Карточка содержит `canonical_id`, `visit_condition` (kind, note, source_url, checked_at, verification).
Ограничения действуют до ранжирования, для локальных и 2ГИС-кандидатов; кандидат не возвращается через подтверждённый другой ID. История — заявление пользователя, не доказательство физического визита.

## F1–F2: маршрут и пересчёт

`POST /plans/build`:

```json
{
  "request": {
    "location": {"lat": 51.128, "lon": 71.430},
    "query": "Прогулка", "source": "local",
    "context": {"time_budget_min": 90, "lang": "ru"}
  },
  "finish_mode": "destination",
  "destination": {"lat": 51.132, "lon": 71.435},
  "stop_ids": [], "completed_ids": [], "skipped_ids": [],
  "reserve_min": 5, "max_stops": 3
}
```

`finish_mode=return` (по умолчанию) возвращает к `origin`, по умолчанию равному текущей точке. Для `destination` финиш обязателен. Пустой `stop_ids` выбирает остановки автоматически; непустой список задаёт порядок до 5 доверенных ID. `max_stops`: 1–5. Не передавать длительности, названия или координаты остановок — сервер читает свои данные/2ГИС. Удобства добавляются по их `poi_id`.

Ответ `PlanResponse`:

- `status`: `ok`, `partial` (часть явно выбранных остановок исключена), `impossible`, `no_matches`, `unavailable`, `refused`.
- `fits`: весь выданный маршрут помещается в бюджет и проходит проверки. Для `no_matches` может быть true для дороги к финишу, но остановок нет. `fits=false` и `do_not_start_plan` запрещают показывать план готовым к прогулке.
- `budget`: available_min, walking_min, visiting_min, reserve_min, total_min, spare_min. `total=walking+visiting+reserve`. Перед вылетом запас минимум 60 минут. Запас не включён в `estimated_arrival_at`.
- `stops`: ID и canonical_id, координаты, название/категория, arrival_at, departure_at, stay_min, open_status, visit_condition, sources.
- `legs`: from_id/to_id (`start`/`finish` либо ID), distance_m, walk_min, source.
- `routing_source`: `osrm_foot` либо `distance_estimate`. Пешеходные расстояния берутся с существующего публичного OSRM; минуты считают с темпом пользователя, ребёнка/зимы. Резервный расчёт — расстояние по прямой × 1.3. Это оценка, не гарантия прохода/прибытия. `geometry` — массив `[lon,lat]`. `routing_error` сообщает о недоступности/локальном ограничении.
- `state`: schema_version=1, created_at, origin, finish_mode, finish, remaining_ids, completed_ids, skipped_ids, preferences, exclude_categories, companions, accessibility, reserve_min.
- `exclusions`: ID и причина, `notes`, `warning_codes`, `source`, `source_error`, `data_kind`, applied_preferences/change_codes/relaxation_options.

Расписание проверяется на всём интервале посещения каждой остановки. Неизвестное расписание остаётся неизвестным. План учитывает ребёнка, доступность, ночное время, погоду, расходы и лимиты ходьбы. Никакой режим не гарантирует безопасность пути.

`POST /plans/recalculate`: `request`, предыдущий `state` в поле `previous`, `reason`, `remaining_time_min` (5–480), `completed_ids` (новые выполненные, до 5), `poi_id` при необходимости, `reserve_min` (по умолчанию 5).

| reason | Поведение |
|---|---|
| `less_time`, `refresh` | Пересчитать оставшиеся остановки |
| `cold` | Искать помещение с переходами до 5 минут |
| `tired` | Переходы до 5 минут |
| `closed`, `busy` | Исключить `poi_id` из текущего плана, подобрать замену |
| `skip` | Исключить `poi_id`, сохранить остальные остановки |
| `add_stop` | Добавить `poi_id`, перепроверить полный бюджет |

Точка начала — новая `request.location`, финиш сохраняется из `previous`. Если `preferences` или `context.exclude_categories` отсутствуют, берётся предыдущее значение; явное пустое значение снимает соответствующее ограничение. Пересчёт начинается сейчас, не повторяет «завтра» из старого текста. `no_matches` при пересчёте возвращается как HTTP 409 `no_replacement_found`: клиент сохраняет предыдущие остановки, геометрию и финиш и объясняет, что новое пожелание ещё не выполнено. Начальное построение сохраняет прежний контракт `no_matches`. Состояние старше 24 часов отклоняется: 409 `stale_plan`, нужно заново построить план. Настоящие координаты не сохраняются в постоянной истории сервера.

Детский режим, доступность и обязательный резерв сохраняются при пересчёте. Фронтенд отсчитывает оставшиеся минуты от момента построения/явного изменения бюджета; при остатке менее 5 минут предлагает новый план. Кнопки не начинают маршрут с fits=false. Пройденные остановки остаются видимыми в UI и передаются как новые completed_ids только если ещё входят в previous.remaining_ids. Ошибка сохраняет предыдущий план с предупреждением. Линия на карте берётся из server.geometry.

## F4: удобства

`POST /comfort/search`:

```json
{"location":{"lat":51.128,"lon":71.430},"route_points":[],"kinds":["toilet","warming"],"radius_m":500,"public_only":false,"verified_only":true}
```

`kinds`: warming/toilet/bench/water/entrance. `route_points`: до 20 точек линии маршрута в формате `{lat,lon}` (не `[lon,lat]`). Передавать точки вдоль фактического маршрута; между ними расстояние считается до отрезка. Пустой список означает поиск вокруг location. Радиус 50–2000 м, максимум 50 результатов.
Ответ — массив `{poi_id,name,coords,kind,access,distance_to_route_m,floor,note,source_url,checked_at,verified}`. Пустой массив допустим. `verified` требует подтверждения не старше 30 дней. `access`: public/customers_only/paid/unknown. Непроверенное удобство можно увидеть с `verified_only=false`, но сервер не включит его в план как подтверждённую остановку.

## F6: сохранение на устройстве

`POST /plans/export`: `{ "schema_version":1, "plan": <запрос /plans/build> }`.
Сервер заново рассчитывает план. Экспортирует только собственные записи с проверенными правами и `offline_allowed=true`; каталог 2ГИС и сторонние фотографии автоматически не копируются.
Ответ `OfflinePlan`: schema_version=1, saved_at, status (saved/not_exportable/revalidation_failed), stops, omitted_ids, contains_full_route, budget, origin, finish, warning_codes, notes.
Для каждого stop: poi_id/name/coords/category/stay_min/sources/checked_at/license/attribution из разрешённой собственной записи. Если сохранена лишь часть остановок, `contains_full_route=false`, budget/origin/finish=null: показывать отдельные сохранённые места, а не полный офлайн-маршрут. Фото и карта не включены. Сохранять снимок в браузере, разрешать удаление.

`POST /plans/refresh`: `{ "saved": <OfflinePlan>, "request": <RecommendRequest>, "reserve_min":5 }`. Обновляет только ID сохранённых мест из доверенных источников, игнорирует старые клиентские названия, координаты и длительности. Для частичного снимка задать финиш через новый `/plans/build`. Старые часы не показывать актуальными. Неизвестная версия формата → 422.

## F8: идентичность

`POST /places/identities`: `{ "poi_ids": ["ID из ответа"] }` → `{schema_version:1,identities:[{poi_id,canonical_id,verified_link}]}`.
Связь источников только из проверенной таблицы Ерлана; одинаковое название не доказывает один филиал. Неизвестный ID возвращается как собственный canonical_id, verified_link=false. Клиент может сохранять оба ID; предпочтения и посещения не отправляются Gemini целиком. API не хранит пользовательскую историю/аккаунты.

## Ошибки, нагрузка, эксплуатация

Структурные ошибки → 422 в прежнем формате валидации приложения. Ошибки новых операций → `{"error":{"code":"..."}}`: 404 poi_not_found; 409 stale_plan/no_replacement_found; 422 outside_astana/duplicate_or_too_many_stops/completion_not_in_plan/stop_not_in_plan/too_many_exclusions/empty_saved_plan. Ошибки провайдера при построении плана → status=unavailable, source_error, fits=false. Ничего не принимать за пустой успешный подбор без проверки status.

Новые endpoint-ы используют существующий CORS и JSON Content-Type; размеры списков и текста ограничены схемами. GET/POST с опубликованного Netlify разрешены. Точные запросы, координаты и заметки не печатаются в прикладные логи. Планы не пишутся в файлы или БД сервера; временный кеш запросов/каталога сохраняет прежние ограничения.

Новых платных сервисов, ключей, БД и пакетов нет. `FEATURE_DATA_DIR=data`; `ROUTING_ENABLED=true` по умолчанию при запуске из окружения (false отключает OSRM). Не более одного обращения OSRM в секунду на процесс, таймаут 3 секунды, при отказе — явная оценка. Лимит Gemini: 12 запросов/минуту, 400/сутки на процесс, фото оставляют 2/минуту и 100/сутки основным запросам, HTTP 429 включает паузу 60 секунд. Эти лимиты сбрасываются при рестарте и не заменяют квоты бесплатного аккаунта провайдера; тарифы автоматически не меняются. 2ГИС использует существующую ограниченную квоту и кеш.

`recommendations[].selection_source` описывает выбор места; текущий алгоритм возвращает `rules`. `why_source` и `what_to_do_source` содержат `ai` для принятого текста Gemini либо `template` для резервного объяснения. Пределы — 25/35 слов. Неизвестные Wi-Fi, розетки и тишина обозначаются явно. Сортировка и длительности остаются за кодом; подробнее в разделе grounded-rag ниже.

Отдельные координаты пользователя/финиша и история ID не передаются Gemini. Текст поиска передаётся, поэтому в него не нужно включать личные сведения. Личные заметки остаются на устройстве. Детали — `frontend/about.html`; новую страницу и подсказку публикует Алихан вместе с остальным frontend.


## Выбор места и восстановление прогулки (19 октября)

- Выбранная карточка или метка хранится только в состоянии интерфейса. «Начать прогулку» из панели выбранного места отправляет `stop_ids: [selected_poi_id]`, `max_stops: 1`. Это относится и к каталогу вне топ-3. Финиш и ограничения сохраняются. Не подменять недоступное выбранное место первым из топ-3.
- «Назад ко всем местам и топ-3» снимает выбор и показывает прежний полный ответ, не запускает поиск. Кнопка построения общего плана использует рекомендации, как раньше.
- Пересчёт принимает только `fits=true`, `status=ok|partial` и непустые `stops`. HTTP-ошибка, пустой ответ или отмена не стирают текущую прогулку.
- История до пяти успешных пересчётов хранится в памяти вкладки. Возврат сохраняет выполненные остановки и не продлевает срок прогулки; старые часы и условия требуют повторной проверки.
- «Закрыть» сворачивает панель; «Продолжить прогулку» открывает её. Только «Закончить прогулку» очищает активный маршрут. Переключение темы/подложки карты не меняет маршрут или выбранное место.


### Остановка согреться без потери цели

`/health.features.nearby_break = 1` разрешает передать `keep_stops: true` в `/plans/recalculate` с `reason: cold|tired`. Без этого флага UI не отправляет новое поле старому серверу.

Сервер ищет одну остановку в помещении примерно до 5 минут пешком от текущей точки, затем проверяет **весь** план: новая остановка → все оставшиеся остановки в прежнем порядке → прежний финиш. Ограничения, условия расходов, состав группы, расписания и общий бюджет сохраняются. Если добавление не помещается или требует убрать прежнюю цель, ответ — 409 `no_replacement_found`. Это не обещание бесплатного входа или свободных сидений: условия показываются отдельно.

Клиент показывает предложение и метку отдельно от активного маршрута. До кнопки «Добавить остановку» прежняя линия и остановки не меняются. Предложение истекает через минуту; отметка выполненной остановки, новый пересчёт и отмена делают его недействительным. После принятия доступен возврат к предыдущему маршруту. Старые клиенты без `keep_stops` сохраняют прежний протокол замены.

Явный `stop_ids` задаёт выбранные места и отменяет лишь выведенную из текста категорию поиска; заданные пользователем ограничения, расписания и проверки безопасности действуют по-прежнему.

## Отдых — дополнение от 19.10.2026

Флаг `/health.features.comfort_breaks=1` включает удобства для остановки.

При cold/tired фронтенд параллельно запрашивает `/comfort/search`: location текущей выбранной точки, radius_m=100, kinds=[warming,bench,toilet,water,entrance], verified_only=true, on_route_only=true и route_points от текущей точки к следующей цели. Проверяется добавочный путь; первоначальная цель сохраняется. ComfortView дополнен distance_m, walk_min (оценка по 60 м/мин и коэффициенту 1.3), indoor и open_status. Источник, дата, этаж и условия доступа видны в карточке. Скамейка на улице не обозначается как место согреться. Закрытые точки показаны с недоступной кнопкой; неизвестные часы подписаны честно.

`keep_stops:true` теперь поддерживает `reason:add_stop` и poi_id. Дополнительная остановка ставится **перед** оставшимися целями, после проверки всего бюджета/часов/расстояния. Ответ остаётся PlanResponse. Фронтенд сначала показывает предложение и применяет его только по подтверждению; проверяет сохранность всех оставшихся ID и финиша. Декор и предпочтительная категория не ограничивают остановку для отдыха; расходные, зимние и прочие ограничения сохраняются. При tired сначала проверяются реальные скамейки в пределах 300 м; cold продолжает искать помещение. Неудача поиска заведений не скрывает независимо загруженные удобства. Данные удобств ограничены обследованными точками команды; отсутствие ответа не означает отсутствие скамеек на местности.

Дневной и ночной заглавные снимки переключаются вместе с системной/выбранной темой. Авторство дневного фото добавлено в img/credits.json. Для публикации Алихану нужен весь актуальный frontend из main; SW v24 обновляет оболочку. Настройки и ключи Render менять не требуется.

## Медленная геолокация — 19.10.2026

SW v25: быстрый ответ браузера применяется сразу, разрешён кэш не старше минуты. Через 3 секунды появляется подсказка и выбор точки на карте; исходный запрос продолжает работать до 15 секунд. Ранее UI окончательно отбрасывал ответы после 5 секунд, в том числе после подтверждения разрешения. Это исправление приёма ответа, а не гарантия ускорения системной геолокации. Поиск и выбор карты никогда не блокируются ожиданием.

Выбор точки, сценария, запуск поиска и начало прогулки отменяют ожидание; устаревшие callbacks не меняют начало или маршрут. Нового фонового отслеживания и хранения координат нет. Полученные координаты округляются на устройстве. Точность браузера показывается отдельно и передаётся в существующем поле location.precision_m (округление вверх до 100 м). При погрешности более 300 м UI просит проверить точку, при погрешности более 1 км или неизвестной точности сохраняет прежнюю точку и предлагает ручной выбор.

Если на Mac координаты не приходят в обоих браузерах, проверить «Системные настройки → Конфиденциальность и безопасность → Службы геолокации», отдельное разрешение сайта и включённый Wi-Fi. Разрешение Safari и Chrome настраивается отдельно. Публикуется весь frontend; сервер, ключи и тариф менять не нужно.

## Одна активная линия — 19.10.2026

SW v26: при начале прогулки пунктирные связи с рекомендациями скрываются отдельным слоем; маркеры и список мест сохраняются. Закрытие панели, смена языка, новые результаты и пересчёт не возвращают этот слой. После явного «Закончить» он снова показывает актуальные рекомендации. При старте также очищаются линии превью/встречи и отменяется применение их запоздавших ответов. Геометрия и обозначение точности активного маршрута не меняются. Публикуется весь frontend; обновление Render не требуется.

## 2026-10-19: context finish and deterministic ranking

`/health.features.finish_preferences=1` enables `RecommendRequest.finish_mode` (`place|return|destination`). `place` leaves the person at each recommended venue; `return` includes the return leg; `destination` requires `end`. Omitted field retains previous behavior. `place/return` with `end` is rejected as contradictory.

`PlanRequest.finish_poi_id`, `PlanState.finish_poi_id`, `OfflinePlan.finish_poi_id` are optional. For staying at a selected place, send plan `finish_mode=destination`, `destination` and its verified ID. The server resolves exact public POI coordinates instead of using rounded private coordinates as the venue's finish. Retain the ID in replans/export requests. Only a complete permitted offline route exports it.

Recommendation order/durations now come from deterministic rules; `ai_reviewed` identifies a validated Gemini draft, while `selection_source=rules`. Shared time formula, UI behavior, backward compatibility and limits: [context_map_release.md](context_map_release.md).
